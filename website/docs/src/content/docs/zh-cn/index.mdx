通过可复用技能、MCP 工具、命令或带作用域的侧栏扩展桌面工作区。OpenAgent 安装 **Agent Plugins 1.0** 格式的包，平台专属能力放在 `extensions.openagent` 中。

先运行一个 Skill 包，再按需添加组件，最后验证实际安装的候选包并发布。创作需要已安装的 OpenAgent、Git 和 Bun，无须构建桌面源码或访问私有 SDK。除非步骤另有说明，命令都从你的项目根目录执行。

## 选择起点

| 想扩展什么 | Plugin Kit 模板 |
| --- | --- |
| 可复用指令 | `minimal` 或 `skill-pack` |
| MCP 服务提供的工具 | `mcp-tools` |
| 斜杠命令 | `slash-commands` |
| 带作用域的侧栏 | `sidebar-panel` |
| 生命周期钩子 | `automation-hooks` |
| 工具租约或受监管的进程 | `mcp-lifecycle` 或 `daemon` |
| 经过校验的外观 token | `theme` |
| 宿主渲染的集成设置 | `integration` |

克隆工具链后，可运行 `bun tools/openagent-plugin-kit/scripts/new-plugin.mjs --list` 查看该源码版本提供的模板。`full-kit` 组合多个界面与能力；学习时先选择小模板，便于定位每个失败的责任边界。

## 参考当前的独立插件

[插件开发助手](https://github.com/BANG404/openagent-plugin-kit) 既是公开工具链，也是可安装的开发助手。[Chat Groups](https://github.com/BANG404/openagent-chat-groups)、[Goal](https://github.com/BANG404/openagent-goal)、[Graph](https://github.com/BANG404/openagent-graph)、[Cua Driver](https://github.com/BANG404/openagent-cua-driver) 和 [Message Board](https://github.com/BANG404/openagent-message-board) 分别独立安装。[工作流章节](./plugins/workflows/)把它们的设计对应到具体开发需求。Multi-Agent V2 属于 Runtime 能力；Goal 和 Graph 通过共享 Host Bridge 实现插件自己的工作流。

## 什么时候可以发布

校验通过只证明包结构正确。还要调用实际安装的工具或命令，检查持久化、失败路径、声明的语言与主题，以及需要认证的真实服务操作。保留测试版本与证据。本地刷新、开发者验收和公开发布是分别进行的步骤，[排错章节](./plugins/local-development/)给出完整流程。

本教程依据当前公开 Plugin Kit 的模板与校验器编写。旧版 Runtime 即使接受插件协议 1，也可能缺少可选的桥接操作，调用前应检测支持情况。逐字段规范以 [Plugin Kit 文档](https://github.com/BANG404/openagent-plugin-kit/tree/main/docs) 为准。
