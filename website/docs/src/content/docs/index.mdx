Extend your desktop workspace with reusable Skills, MCP tools, commands, or a scoped sidebar. OpenAgent installs **Agent Plugins 1.0** packages; its additional capabilities live under `extensions.openagent`.

Start with a working Skill package, add only the components you need, then verify the installed candidate before publishing. You need an installed OpenAgent, Git, and Bun for authoring; you do not need a desktop source build or access to the private SDK. All commands use your project root unless a step says otherwise.

## Choose a starting point

| What you want to add | Plugin Kit template |
| --- | --- |
| Reusable instructions | `minimal` or `skill-pack` |
| Tools from an MCP server | `mcp-tools` |
| A slash command | `slash-commands` |
| A scoped side panel | `sidebar-panel` |
| Lifecycle hooks | `automation-hooks` |
| Tool leases or a supervised process | `mcp-lifecycle` or `daemon` |
| Validated appearance tokens | `theme` |
| Host-rendered integration setup | `integration` |

Use `bun tools/openagent-plugin-kit/scripts/new-plugin.mjs --list` after cloning the kit to see the templates available at your checked-out revision. `full-kit` combines several surfaces; start smaller when learning so each failure has a clear owner.

## Learn from current packages

[Plugin Developer](https://github.com/BANG404/openagent-plugin-kit) is both the public toolchain and an installable development assistant. [Chat Groups](https://github.com/BANG404/openagent-chat-groups), [Goal](https://github.com/BANG404/openagent-goal), [Graph](https://github.com/BANG404/openagent-graph), [Cua Driver](https://github.com/BANG404/openagent-cua-driver), and [Message Board](https://github.com/BANG404/openagent-message-board) are independently installed packages. The [workflow chapter](./plugins/workflows/) maps their designs to concrete authoring needs. Multi-Agent V2 is a Runtime capability; Goal and Graph add package-owned workflows through the shared Host Bridge.

## What “ready to publish” means

A validator pass proves package structure. Also exercise real installed tools/commands, persistence and failure paths, declared languages and themes, and any authenticated service operation. Keep the tested revision and evidence. Local source refresh, developer acceptance, and public release publication are separate steps; the [debugging chapter](./plugins/local-development/) walks through them.

These tutorials follow the current public Plugin Kit templates and validator. An installed older Runtime may lack optional bridge operations even if it admits plugin protocol 1; detect support before using them. Public field-by-field references stay in the [Plugin Kit documentation](https://github.com/BANG404/openagent-plugin-kit/tree/main/docs).
