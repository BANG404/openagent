# Codex CI auto-fix

The repository's Codex repair workflow is `.github/workflows/codex-autofix.yml`.
It listens for a failed `CI` workflow, downloads that run's logs, runs Codex on
the WSL self-hosted runner, and pushes a `codex/autofix-<run-id>` branch when
the working tree changes.

## Trust boundary

The workflow runs only for a failed `pull_request` CI run whose head repository
is this repository and whose author has administrator permission. Fork pull
requests and non-administrator contributors never reach the self-hosted job or
receive `CODEX_API_KEY`. Keep this gate when changing the workflow; a
`workflow_run` workflow can access repository secrets.

The WSL runner must be dedicated to this repository. Do not keep personal files,
SSH private keys, or unrelated source trees in its account. The Codex command
uses full access because the runner is an explicitly trusted host; do not move
this job to a shared or public self-hosted runner.

## WSL runner setup

Enable WSL2 and install a Linux distribution from an elevated Windows terminal:

```text
wsl --install -d Ubuntu-24.04
wsl --set-default-version 2
```

Inside the distribution, install `git`, `curl`, `unzip`, `gh`, Bun, and the
Linux Codex CLI. Register a new Linux runner from the repository settings with
the labels `self-hosted,wsl,codex-agent`. Keep the repository's existing
platform Runner assignments unchanged; this WSL Runner is only for Codex repair.

For persistent service execution, enable systemd in `/etc/wsl.conf`:

```ini
[boot]
systemd=true
```

After `wsl --shutdown`, install and start the runner service with the commands
generated by GitHub:

```bash
sudo ./svc.sh install
sudo ./svc.sh start
```

## Codex configuration

Create the configuration for the Linux user that owns the Runner service at
`~/.codex/config.toml`. Keep the Provider key out of this file:

```toml
model = "gpt-6-sol"
model_reasoning_effort = "medium"
model_provider = "firedog"
approval_policy = "never"
sandbox_mode = "danger-full-access"

[model_providers.firedog]
name = "Company Provider"
base_url = "https://provider.example.com/v1"
wire_api = "responses"
env_key = "CODEX_API_KEY"
```

Add `CODEX_API_KEY` as a repository Actions secret. The workflow passes it only
after the trust gate succeeds. Confirm that the Runner service account can find
both `codex` and `gh` in its `PATH`; an interactive shell's PATH is not always
available to a WSL service.
